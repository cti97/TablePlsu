# TablePlsu — Architecture

The feature list is in [spec.md](spec.md). This document fixes the structure, so features can be built in parallel without stepping on each other.

## Stack
- .NET 10, WPF (`net10.0-windows`), C# latest, nullable enabled, warnings as errors in Core.
- Npgsql 10 (DB), SSH.NET (tunnel), AvalonEdit (editor), CommunityToolkit.Mvvm (MVVM source generators).
- Tests: xUnit. Integration tests read the `TABLEPLSU_TEST_PG` env var (an Npgsql connection string) and **skip** when it is unset. The local fixture is `Host=localhost;Port=54329;Username=postgres;Database=tableplsu_test`, seeded by `tests/seed.sql` (start it with `scripts/start-testdb.sh`).

## Speed rules (non-negotiable)
1. Startup does no DB or network work, does not touch Npgsql types, and does no reflection scanning. `App.OnStartup` loads settings, theme and connections (small JSON files) and shows the window. Everything else is lazy.
2. Publish with `ReadyToRun`, `TieredPGO`, `TieredCompilation`, `InvariantGlobalization=false`, `SatelliteResourceLanguages=en`. Startup is measured by `--measure-startup`, which logs ms to first `ContentRendered` and exits. `scripts/publish.ps1` publishes **self-contained with `PublishReadyToRunComposite`** (runtime + WPF + app in one composite R2R image: ~560 methods jitted at startup instead of ~1,700; ~205 MB on disk instead of ~23 MB); `-FrameworkDependent` gives the small build. Compare builds with `scripts/measure-startup.ps1 -Exe a.exe,b.exe -Runs 7` (interleaved).
   First window (speed/windowshow, `Infrastructure/StartupWarmup`): `Program.RunApp` starts a multi-core JIT profile (`%LOCALAPPDATA%\TablePlsu\cache\startup.jitprofile`; `--measure-startup` uses `startup-measure.jitprofile`) and a short-lived "Render warm-up" STA dispatcher thread whose `MediaContext` starts WPF's process-wide render system in parallel with App/App.xaml/MainWindow construction; the first window's first frame is rendered in software (`RenderOptions.ProcessRenderMode`), and hardware rendering is restored for it (its `HwndTarget` mode is toggled so the target is re-created) in the post-render idle callback, which also stops the warm-up thread. Touch/pen use the WM_POINTER stack (`Switch.System.Windows.Input.Stylus.EnablePointerSupport` in the csproj): WISP's tablet enumeration cost 35-100 ms inside `Window.Show`. `--measure-startup` also reports UI-thread JIT and UI-thread CPU cycles per mark (`ui mcycles`, load-insensitive) and `hw` (time to get back to hardware rendering); compare builds with `scripts/perf-windowshow.ps1`.
3. All DB I/O is async and runs off the UI thread. Results stream in batches of 200 rows into a buffer (`SqlEditor/ResultBatchPump`); the UI drains everything buffered so far in one Background-priority operation at most every 50 ms (a statement's first batch and its final batch at once), appending each statement's rows with one `AddRange`, and yields after ~20 ms so input and rendering keep running. Never one UI operation per batch: WPF pays a layout pass per operation. `scripts/perf-streaming.ps1` measures it.
4. Grids are virtualized (`EnableRowVirtualization`, `EnableColumnVirtualization`, `VirtualizingPanel.VirtualizationMode=Recycling`). Rows are `object?[]`, and columns bind via `Binding("[i]")` with a shared null/format converter.

## Core layout (namespace = folder)
| Folder | Owns |
|---|---|
| `Paths/AppPaths.cs` | `%APPDATA%\TablePlsu`, `%LOCALAPPDATA%\TablePlsu`, overridable root for tests. |
| `IO/AtomicFile.cs` | Write to temp, then `File.Replace`/`Move`. Used for every write. |
| `Settings/` | `AppSettings` (typed record tree mirroring spec §13 keys), `SettingsService` (embedded `defaults.json` deep-merged with the user `settings.json`, `FileSystemWatcher` hot reload, `Changed` event, keeps the last good config on parse errors and exposes `LastError`). |
| `Themes/` | `ThemeDefinition` (base + flat `Dictionary<string,string>` colours keyed like `editor.keyword`), `ThemeService` (built-in light/dark embedded JSON, user `themes\*.json`, overrides). |
| `Keymap/` | `KeyChord` parse/format ("Ctrl+Shift+Enter"), `KeymapService` (defaults from `CommandIds` + user overrides, conflict detection). |
| `Commands/CommandIds.cs` | String constants for every command id plus their default bindings. |
| `Connections/` | `ConnectionProfile` (id, name, color, tag, safeMode, host, port, user, db, passwordMode, ssl*, ssh*, bootstrap, rowLimit), `ConnectionStore` (connections.json), `SecretStore` (DPAPI, file-backed), `ConnectionUrl` (parse/format postgresql:// and postgresql+ssh://). |
| `Db/` | `DbSession` (one per open workspace: owns the SSH tunnel, the `NpgsqlDataSource`, and separate query and metadata connections; Connect/Reconnect/Disconnect/KeepAlive; `ExecuteAsync(sql, rowLimit, IProgress<ResultBatch>, ct)` streams results per statement; cancel via `NpgsqlCommand.Cancel`), `QueryResult` / `ResultColumn` / `ResultBatch` / `StatementResult` (columns, rows `object?[]`, affected, notices, error with position, elapsed), `SshTunnel`. |
| `Sql/` | `StatementSplitter` (PG-aware: quotes, `$tag$`, comments, E'' strings; returns spans with offsets; `StatementAt(caret)`), `SqlIdent` (quoting), `TabNameDirective` (`-- name:`), `SqlFormatter` (P1). |
| `Metadata/` | `DbMetadata` model (schemas → tables/views/matviews/functions/sequences/types, columns, PK, FKs, indexes), `MetadataLoader` (catalog queries), `MetadataCache` (JSON on disk per connection+db, memory, background refresh). |
| `Completion/` | `CompletionEngine`: pure function `(text, caret, DbMetadata, options) → CompletionItem[]`, alias/CTE aware. |
| `Data/` | `TableQueryBuilder` (SELECT with filters, sort, paging, parameterized), `FilterCondition` and operators, `PendingChanges` (staged cell edits, inserts, deletes, DDL ops, undo/redo), `ChangeSqlGenerator` (UPDATE/INSERT/DELETE by PK, parameter-safe literal rendering for preview), `DdlGenerator` (CREATE TABLE, column ops), `SafeModePolicy`. |
| `Editors/` | `EditorSessionStore` (autosave: `editors\{connId}\{tabId}.sql` plus `session.json`, debounced, recently-closed list). Writes are serialized (`Flush` waits for an in-flight write; failed writes stay pending and retry). Several stores (windows, processes) may share one connection: each owns the tabs it restored/created, session.json changes are read-merge-write under a named mutex, `LoadTabs` skips tabs another live store has open, orphan `.sql` files are recovered as tabs, a corrupt session.json is backed up. App: `EditorSessionManager.FlushAll()` runs on unhandled exceptions (UI and AppDomain), `SessionEnding` and exit. |
| `History/` | `HistoryStore` (JSONL per connection, capped). |
| `Search/` | `FuzzyMatcher` (used by the palette and sidebar). |

### Extension points (defined by the foundation and stable after it)
- `IFeature { void Register(FeatureContext ctx); }`, listed explicitly in `Infrastructure/Features.cs` (one line per feature, no reflection). `FeatureContext` exposes `CommandRegistry`, the tab factory registry (`ctx.Tabs.Register(kind, Func<TabRequest, TabViewModelBase>)`), sidebar context menu contributors, palette item providers, and toolbar items.
- `TabRequest { Kind, Schema, Name, ObjectKind, Sql, Pinned, InNewTab }`. The workspace calls `OpenTab(request)`, which applies the preview-tab reuse rules from the spec.
- `IWorkspace` (what features see): `DbSession Session`, `ConnectionProfile Profile`, `string Database`, `MetadataCache Metadata`, `OpenTab`, `ActiveTab`, `Log(string)` to the console, `History`, `SafeMode.ConfirmAsync(statements)`.

#### As built (App shell)
- `FeatureContext` also has `Panels.Register(WorkspacePanel.Sidebar|Console|Right, ws => element)` for the layout slots, `OnWorkspaceOpened(ws => …)` (restore editor tabs here, before the connection finishes), `OnWindowCreated`, and `UseSafeMode(ws => ISafeModeGate)`.
- Command handlers: `ctx.Commands.Register(id, Action<CommandContext>, Func<CommandContext,bool>? canExecute)`. `CommandContext` carries `Workspace`, `Target` (DataContext of the nearest element marked `infra:CommandScopes.Scope="Editor|Grid|Sidebar|FilterBar"`), `IsTextInputFocused`. The newest handler whose `canExecute` passes runs. A scope element's DataContext implementing `ICommandTarget` gets the command first; workspace-scope commands are forwarded to the active tab when it implements `ICommandTarget`.
- Tabs: `TabViewModelBase` (`Kind`, `Schema`, `Name`, `Title`/`CustomTitle`, `IsDirty`, `IsPreview`, `HasPendingChanges`, `IsBusy`, `CreateView()`, `Save/CommitAsync/PreviewChanges/DiscardChanges/Reload/Flush/CanCloseNow/OnClosed`). Factories: `ctx.Tabs.Register(TabKinds.X, request => vm)` (or `(request, workspace) => vm`). Views are created once per tab and cached by `TabHost`.
- `IWorkspace.Metadata` is the workspace's `MetadataCache` (Core `Metadata/`): disk cache loaded on open, server refresh after each (re)connect and on Ctrl+R (`workspace.reload`). `Changed` fires on a background thread; marshal with `UiDispatch`. Read `ws.Metadata.Current` (an immutable `DbMetadata` snapshot) or use `FindTable(schema?, name)` / `FindFunctions` / `EnsureSchemaLoadedAsync(schema)` (lazy mode, `sidebar.lazyLoadSchemas`).
- `Features/Results/ResultGrid` is the shared grid: set `ResultColumns` + `Rows` (a `BulkObservableCollection<object?[]>`, append with `AddRange`). Display cells are `CellText` elements (no per-cell bindings). Editable mode: `IsReadOnly=false`, `CellEditCommitted`, `RowStateProvider`, `RefreshRow`. Header clicks raise `SortRequested` (`ServerSort=true` disables client sorting; show order with `SetSortIndicators`). `grid.copy` / `grid.copyCells` are handled by `ResultsFeature`. Grid font resources: `grid.fontFamily`, `grid.fontSize`, `grid.cellPadding`, `grid.rowHeight` (`GridResources`).
- Settings (`Features/Settings`): `settings.open` (Ctrl+,) opens settings.json as a `TabKinds.Settings` tab (a stand-alone window on the welcome screen); `keymap.open` reveals the `"keymap"` section and opens the `keymapReference` tab; extra unbindable commands `settings.openDefaults`, `keymap.reference`, `themes.openFolder` (also palette items). Validation: Core `SettingsValidator` (embedded schema subset + keymap warnings, line/column diagnostics). Font resources for live settings: `editor.fontFamily` / `editor.fontSize` / `editor.lineHeight` and `sidebar.fontFamily` / `sidebar.fontSize` / `sidebar.rowPadding` (Thickness) / `sidebar.rowHeight` (`SettingsResources`, published after first render) — bind them with `{DynamicResource …}`. Views that cache settings values on construction must subscribe to `AppServices.SettingsChanged` (tags colours are refreshed by the Settings feature). Built-in themes: Light, Dark, Nord, Solarized Light; `themes\*.json` is watched.
- Sidebar (`Features/Sidebar`): one `SidebarViewModel` per workspace in `ws.Services` (`SidebarFeature.For(ws)`; `RevealSchema`, `RequestFocusSearch`). Object actions live in `SidebarActions` (open/preview/pinned/new tab, "Open structure" = the object's `TabRequest` with `Parameter = "structure"`, function tabs get `Parameter = FunctionInfo` and `Title = signature`, New Table = `TabKinds.CreateTable` with `Schema`). Truncate…/Delete… run immediately through `ws.SafeMode` (not staged). SQL text for Copy Script As is `Core/Sidebar/ScriptGenerator`. Search: `SidebarIndex` (per metadata snapshot: items sorted, row nodes built once) + allocation-free `FuzzyMatcher.IsMatch`; with >= 1000 candidates the Items and History searches run on the thread pool after `sidebar.searchDebounceMs` (default 120), cancel the previous search, apply only the newest result and skip identical results; smaller lists filter synchronously; clearing restores the pre-search selection. Measure with `scripts/perf-sidebarsearch.ps1`. Palette (`Features/Palette`): `PaletteWindow.Open(mode, ws, owner)`; rows are replaced with one Reset per keystroke; items come from `ctx.Palette` providers (`BuiltInPaletteProvider` adds objects, schemas, databases from `DatabaseList`, open SQL tabs, commands, connections).
- Toolbar item ids are the `settings.toolbar.items` names; built-in templates are `tb.<id>` in `WorkspaceView.xaml`. Colours are `{DynamicResource c.<theme key>}` brushes (plus `color.<key>` Colors); shared styles live in `Shell/Styles.xaml`.
- Startup / single instance / resident mode: the entry point is `Program.Main` (`<StartupObject>`), which runs before any WPF type loads. It parses `Core/Startup/LaunchArgs` (`--background`, `--measure-startup`, `--measure-activation`, `--quit`, a `postgresql://` URL) and takes `Core/Startup/SingleInstance` (named mutex `Local\TablePlsu-<hash of user + data root>`; whoever creates it is primary). A second launch forwards its args over the named pipe of the same name (`PipeOptions.CurrentUserOnly`, binary message, one-byte ack) and exits; the primary (`Shell/ResidentMode.HandleLaunch`) activates a window (the visible one, else the hidden one, else a new one) and opens the URL. **Decision:** single-instance forwarding is always on, so a double launch brings the running window forward (Ctrl+N still opens more windows) instead of starting a second process; `--measure-startup` always runs standalone and `TABLEPLSU_ROOT` scopes the name, so test/portable runs never talk to the user's instance. Resident mode (`general.keepRunningInTray` or `general.startWithWindows`, both off by default, applied live): closing the last window flushes every window's autosave (`MainViewModel.FlushAutosave`) and hides it, workspace and connection kept, behind a `Shell_NotifyIcon` tray icon (`Infrastructure/TrayIcon`, P/Invoke, no WinForms) with Open / New Window / Quit. Quit (and `TablePlsu.App.exe --quit`) closes every window the normal way (pending-change prompts can cancel it; all workspaces stay in the reopen list) and exits; `SessionEnding` flushes too. `startWithWindows` writes `HKCU\…\Run\TablePlsu = "<exe>" --background` (`Infrastructure/RunAtLogin`, only for the default data root); `--background` builds and renders the main window once offscreen, hides it, and defers workspace restore to the first Open. Measure with `scripts/measure-activation.ps1`.

## Data flow: run query
Editor → `StatementSplitter` → `SafeModePolicy` check → `DbSession.ExecuteAsync` streams `ResultBatch` per statement → `ResultBatchPump` buffers them on the query thread and flushes coalesced batches on the UI thread → the result tab VM appends them to a `BulkObservableCollection<object?[]>` (`AddRange` raises one Add per row, which keeps scroll position and selection; a Reset on a large grid re-lays out every row, jumps the scroll offset and drops the selection) → the grid renders. `RunAsync` awaits `ResultBatchPump.CompleteAsync` before finishing the run, so every row is in its tab when the run completes. History entry and console log are written per statement.

## Persistence (all atomic, all under AppPaths)
`settings.json`, `connections.json`, `secrets.dat` (DPAPI), `themes\`, `editors\`, `history\`, `cache\metadata\`.

## Testing conventions
- Core logic is TDD'd: splitter, URL parsing, settings merge, keymap parse, query builder, change SQL generator, completion engine, autosave store, history store, fuzzy matcher.
- Integration tests (`[SkippableFact]`-style: return early with a skip message when the env var is missing) for DbSession streaming/cancel, metadata loading and commit transactions.
- The App is verified by building plus running `TablePlsu.App.exe --measure-startup`, and by a UI smoke script where practical.
- End-to-end UI flows: `scripts/ui-flows.ps1 [-Publish] [-Only "flow,flow"]` runs `tests/TablePlsu.UiFlows` (a console exe, not part of `dotnet test`) against the published app on a temp `TABLEPLSU_ROOT`: real keystrokes via `SendInput` (virtual keys), UI Automation only to find and read elements, every P0 flow of the spec, then a pass/fail matrix. Needs an unlocked interactive desktop and the test DB (it creates and drops a scratch table and `tableplsu_test_2`). `--probe orders|typing|db` are diagnostic modes.
- Integration wiring (merge): `CompletionFeature` sets `SqlEditorHooks.AttachCompletion` (returns an `IDisposable` the editor view disposes on tab close). `StructureFeature` registers `StructureViews` into TableData's `TableSubViewRegistry` (`structure`, `indexes`, `ddl`). Sidebar "Open structure" opens `TabKinds.Structure` for tables and `viewDdl` for views/matviews; the function tab accepts a `FunctionInfo` as `TabRequest.Parameter`. `SafeModeFeature` installs the real `SafeModeGate`.
- Customisation (fix/custom): `ThemeApplier` also maps the Windows `SystemColors` brush keys onto the theme (AvalonEdit search panel, scroll-viewer corner, default selection); `Shell/Styles.xaml` themes `ScrollBar`, `DataGridColumnHeader` and the DataGrid select-all corner. `editor.lineHeight` is applied by `SqlEditor/LineSpacingGenerator` (multiple of the font size). Live without restart: `editor.autoSaveDebounceMs`, `editor.defaultRowLimit` (until the connection remembers a limit), `table.pageSize` (until the tab's limit is set), `connections.keepAlive` (`DbSession.SetKeepAlive`), `sidebar.lazyLoadSchemas`/`loadSystemSchemas` (metadata reload). `SettingsService.SetValue` edits settings.json text in place (comments kept).
